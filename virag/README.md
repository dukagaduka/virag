# virag — pixel-RAG proxy

An **OpenAI-compatible `/v1` proxy** that turns on pixel-RAG **on demand**. Point your
OpenAI client at virag and it behaves like an ordinary vision model — until a request
carries a `rag` field, at which point virag retrieves document-image tiles from a
Qdrant + [doc-tiler](../doc-tiler) backend, injects them into the prompt, and forwards
the augmented request to the upstream model. One endpoint; retrieval is opt-in per
request.

- Retrieval is screenshot/pixel RAG (ColPali/PixelRAG style): documents are rendered to
  image tiles, embedded with a multimodal model, and searched as vectors — no OCR, no
  text extraction.
- virag is the **gateway only**. Tiling lives in doc-tiler, embedding in a vLLM server,
  vectors in Qdrant, generation in the upstream VLM.

---

## Quickstart

```bash
cd deploy
cp .env.example .env     # set TILER_DB_SECRET, VLM_BASE_URL, VLM_MODEL_NAME, QDRANT_VECTOR_SIZE
docker compose up --build
curl -s localhost:48000/ready | jq

# enroll a document
curl -s -X POST localhost:48000/enroll \
     -F doc_type=PDF -F document=@report.pdf \
     -F 'metadata={"name":"2024 Annual Report"}' | jq

# ask a question with RAG on
curl -s localhost:48000/v1/chat/completions -H 'content-type: application/json' -d '{
  "model": "my-vlm",
  "messages": [{"role": "user", "content": "What was Q3 revenue?"}],
  "rag": {"top_n": 8, "include_sources": true}
}' | jq
```

Without the `rag` field the same endpoint is a plain passthrough to the upstream model.
Interactive API docs (live OpenAPI): <http://localhost:48000/docs>.

## How a RAG request flows

1. `rag` field present → build a query from the last user message.
2. Embed it, search Qdrant for the top-`N` tiles.
3. Regenerate each tile from the tiler and **verify its hash** against the value stored
   at enroll time (mismatches are dropped).
4. Prepend framing text + the tile images to the last user message.
5. Forward to the upstream VLM; optionally return the retrieved `sources`.

See [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) for the details, including how sources
are spliced into a streaming response.

## Layout

```
virag/
  main.py            app, lifespan (clients, fatal dependency checks, binding, reconcile), router order
  settings.py        Settings.from_env() — every env var and its validation
  binding.py         the TILER_DB_SECRET triple-binding + tiler metadata-schema guard
  reconcile.py       Qdrant ⊆ Tiler self-repair (startup + periodic) and /revision re-embed
  errors.py          ApiError + the uniform {"error": {...}} envelope
  api/               chat_completions, enroll, revision, proxy, ops
  clients/           embeddings_client, qdrant_store, tiler_client, vlm_client
docs/                documentation (see the table above)
deploy/              docker-compose.yaml + .env.example + tiler metadata schema + vLLM serve script
```

## Development

```bash
pip install -e '.[dev]'    # fastapi, httpx, qdrant-client, pytest
pytest -q                  # tests live in tests/
```

Run the app locally against reachable backends:

```bash
uvicorn virag.main:app --host 0.0.0.0 --port 8080
```

(Use whatever Python environment tooling you prefer — a venv or a conda/mamba env with
the dependencies installed; virag doesn't require a specific one.)

Requires `QDRANT_VECTOR_SIZE`, `VLM_BASE_URL` and `VLM_MODEL_NAME` in the environment
(see [docs/CONFIG.md](docs/CONFIG.md)); every backend is checked at startup and a
failure aborts the boot.
